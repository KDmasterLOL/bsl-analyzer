## ADDED Requirements

### Requirement: Неизвестный получатель не квалифицируется как модуль
Диагностика `UnresolvedMethodCall` для `ReceiverNotResolved` или `ReceiverNameAbsent` MUST называть неизвестную сущность получателем вызова и MUST NOT утверждать, что она является модулем. Диапазон и существующий код диагностики SHALL сохраняться; сообщения для доказанно существующего модуля с отсутствующим или неэкспортным методом MUST сохранять прежний смысл.

#### Scenario: Опечатка в имени переменной-получателя
- **WHEN** код обращается к методу через имя, которое не разрешается ни как переменная, ни как модуль
- **THEN** `UnresolvedMethodCall` указывает неизвестного получателя и не содержит утверждения `Не удалось разрешить модуль`

#### Scenario: Метод отсутствует у известного модуля
- **WHEN** общий модуль разрешён, но запрошенного метода в его доступном API нет
- **THEN** диагностика по-прежнему сообщает об отсутствующем методе у известного получателя

### Requirement: Неизвестный оператор локализуется на исходном токене
Parser MUST создавать первичную структурированную ошибку на диапазоне самостоятельного идентификатора, который не образует допустимый BSL-оператор. После такой ошибки parser MUST восстановиться на границе оператора или известном терминаторе и MUST NOT заменять первичную причину только каскадом ошибок на последующих терминаторах или в конце файла.

#### Scenario: Опечатка в КонецЕсли
- **WHEN** блок `Если` закрывается самостоятельным токеном `КонецЕслли;`, после которого расположен корректный `КонецПроцедуры`
- **THEN** среди `ParseError` есть ошибка на точном диапазоне `КонецЕслли`
- **AND** результат не состоит только из сообщений на `КонецПроцедуры` и в конце файла

#### Scenario: Восстановление после неизвестного оператора
- **WHEN** между корректными операторами находится неизвестный самостоятельный идентификатор с `;`
- **THEN** parser сообщает ошибку на этом идентификаторе и продолжает разбирать следующий корректный оператор

#### Scenario: Допустимый идентификатор не считается оператором с опечаткой
- **WHEN** идентификатор используется в допустимом присваивании, вызове или выражении
- **THEN** новый путь восстановления не создаёт для него `ParseError` неизвестного оператора

### Requirement: Отсутствующее поле диагностируется только у закрытой структуры
Анализатор MUST выдавать существующий `UnresolvedField`, когда получатель является доказанно закрытым литералом `Структура` и запрошенного поля нет среди его ключей. Если полнота ключей не доказана, получатель допускает динамическую мутацию или escape, анализатор MUST сохранять мягкое разрешение отсутствующего поля без отрицательной диагностики.

#### Scenario: Отсутствующее поле прямого литерала
- **WHEN** локальная переменная создана как `Новый Структура("СуществующееПоле", 5)` и без последующей неизвестной мутации читается `НесуществующееПоле`
- **THEN** анализатор выдаёт один `UnresolvedField` на `НесуществующееПоле`

#### Scenario: Существующее поле прямого литерала
- **WHEN** у той же закрытой структуры читается `СуществующееПоле`
- **THEN** поле разрешается и `UnresolvedField` не создаётся

#### Scenario: Динамически расширяемая структура
- **WHEN** структура получает ключ из нелитерального выражения, передаётся в неизвестный изменяющий вызов либо её замкнутость иначе не доказана
- **THEN** чтение неизвестного поля не создаёт `UnresolvedField`

#### Scenario: Completion закрытой структуры
- **WHEN** IDE запрашивает completion или hover для закрытой структуры
- **THEN** доказанные ключи отображаются так же, как до изменения, независимо от включения отрицательной диагностики
