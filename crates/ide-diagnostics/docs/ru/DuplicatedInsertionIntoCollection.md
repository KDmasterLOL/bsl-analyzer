# Повторное добавление/вставка значений в коллекцию (DuplicatedInsertionIntoCollection)

## Описание диагностики

Диагностика обнаруживает последовательные вызовы методов добавления или вставки (например, `Добавить`, `Вставить`) с одними и теми же аргументами в пределах одного блока кода. Дублирование таких вызовов, как правило, является ошибкой копирования: разработчик скопировал строку, но забыл изменить значение параметра. В результате коллекция содержит дублирующиеся элементы, что может привести к некорректной работе алгоритма.

Текущая реализация различает два случая:

- для `Добавить` / `Add` сравниваются все аргументы;
- для `Вставить` / `Insert` сравнивается только первый аргумент, то есть ключ.

Также в диагностике есть локальные правила:

- некоторые специальные значения допускается вставлять повторно (`Неопределено`, `Null`, `0`, пустые строки, `Символы.*`);
- переназначение переменной или её родительского пути сбрасывает отслеживание дублей;
- параметр `isAllowedMethodADD` позволяет отключить проверку `Добавить` и оставить только `Вставить`.

## Примеры

### Неправильно

```bsl
СписокДокументов = Новый Массив;
СписокДокументов.Добавить("Приходная накладная");
СписокДокументов.Добавить("Приходная накладная"); // дубль -- вероятно, ошибка

Параметры = Новый Структура;
Параметры.Вставить("Организация", ТекОрганизация);
Параметры.Вставить("Организация", ТекОрганизация); // повторная вставка того же ключа
```

### Правильно

```bsl
СписокДокументов = Новый Массив;
СписокДокументов.Добавить("Приходная накладная");
СписокДокументов.Добавить("Расходная накладная");

Параметры = Новый Структура;
Параметры.Вставить("Организация", ТекОрганизация);
Параметры.Вставить("Контрагент", ТекКонтрагент);
```
