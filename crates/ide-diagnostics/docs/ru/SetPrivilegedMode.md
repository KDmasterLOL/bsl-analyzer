# Использование привилегированного режима (SetPrivilegedMode)

## Описание диагностики

Диагностика обнаруживает вызовы метода `УстановитьПривилегированныйРежим`. Привилегированный режим отключает проверку прав доступа текущего пользователя, что потенциально опасно, особенно во внешних отчётах и обработках. Вызов `УстановитьПривилегированныйРежим(Ложь)` ошибкой не считается.

Особую угрозу представляют экспортные процедуры и функции серверного API, которые безусловно включают привилегированный режим перед выполнением действий с данными. Такой код позволяет любому пользователю обойти ограничения прав доступа.

Если привилегированный режим действительно необходим, следует предварительно выполнить проверку прав вызовом `ВыполнитьПроверкуПравДоступа`, чтобы гарантировать, что текущий пользователь имеет на это полномочия.

## Примеры

Неправильно — безусловное включение привилегированного режима в экспортном методе

```bsl
Процедура УдалитьДанныеОбъекта(СсылкаНаОбъект) Экспорт
    УстановитьПривилегированныйРежим(Истина);
    Объект = СсылкаНаОбъект.ПолучитьОбъект();
    Объект.Удалить();
КонецПроцедуры
```

Правильно — предварительная проверка прав

```bsl
Процедура УдалитьДанныеОбъекта(СсылкаНаОбъект) Экспорт
    ВыполнитьПроверкуПравДоступа("Удаление", СсылкаНаОбъект.Метаданные());
    УстановитьПривилегированныйРежим(Истина);
    Объект = СсылкаНаОбъект.ПолучитьОбъект();
    Объект.Удалить();
КонецПроцедуры
```

Правильно — без привилегированного режима (платформа сама проверит права)

```bsl
Процедура УдалитьДанныеОбъекта(СсылкаНаОбъект) Экспорт
    Объект = СсылкаНаОбъект.ПолучитьОбъект();
    Объект.Удалить();
КонецПроцедуры
```
