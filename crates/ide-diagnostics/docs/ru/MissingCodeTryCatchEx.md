# Блок «Исключение» подавляет ошибку (MissingCodeTryCatchEx)

## Описание диагностики

Блок `Исключение` не должен оставаться пустым. Перехват исключения без какой-либо обработки скрывает реальные ошибки, которые впоследствии крайне сложно диагностировать. Как минимум, необходимо записать информацию об ошибке в журнал регистрации, чтобы администратор мог обнаружить и проанализировать проблему.

Текущая реализация классифицирует тело `Исключение` и срабатывает в трёх
случаях:

- блок пустой (нет операторов);
- блок «молча подавляет» ошибку — содержит операторы, но среди них нет ни
  `ВызватьИсключение`, ни вызова журналирования/уведомления;
- блок только откатывает транзакцию (`ОтменитьТранзакцию()`), не записывая
  ошибку и не пробрасывая её дальше — для этого случая выдаётся отдельное
  сообщение, рекомендующее добавить логирование или `ВызватьИсключение`.

Журналированием считается как платформенный API (`Сообщить`,
`ЗаписьЖурналаРегистрации`, `Message`, `WriteLogEvent`), так и
прикладные/БСП-хелперы, узнаваемые по имени: глагол записи или уведомления
вместе с существительным об ошибке — `ЗаписатьОшибкуВЖурналРегистрации`,
`ДобавитьСообщениеДляЖурналаРегистрации`, `СообщитьОбОшибке`,
`СообщитьОПроблеме`, `ПоказатьПредупреждение` и т. п. Чистые форматтеры
(`ПодробноеПредставлениеОшибки`, `ОписаниеОшибки`) журналированием не
считаются: блок, который только форматирует ошибку, остаётся «молчащим».

Корректные пути восстановления — re-raise, журналирование, или их
комбинация — диагностику не вызывают.

Есть отдельная настройка `commentAsCode`:

- при `commentAsCode = true` блок `Исключение`, содержащий только комментарии, не считается пустым.

## Примеры

Неправильно:

```bsl
Попытка
    ЗагрузитьДанныеИзФайла(ПутьКФайлу);
Исключение
КонецПопытки;
```

Правильно:

```bsl
Попытка
    ЗагрузитьДанныеИзФайла(ПутьКФайлу);
Исключение
    ЗаписьЖурналаРегистрации(НСтр("ru = 'Загрузка данных'"),
        УровеньЖурналаРегистрации.Ошибка,,,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
КонецПопытки;
```
