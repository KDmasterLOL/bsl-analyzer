# Присваивание свойству глобального контекста

Диагностика срабатывает на присваивание голому имени, которое обозначает свойство глобального контекста, — например коллекции менеджеров метаданных (`Справочники`, `Документы`, `Перечисления`, `РегистрыСведений`, …), причём как в русском, так и в английском написании.

## Почему это проблема

Такое имя принадлежит не вашему модулю, а глобальному контексту, и его свойства доступны только для чтения. Присваивание им **не объявляет локальную переменную**: платформа отвергает запись, а имя во всём теле метода продолжает обозначать ту же коллекцию.

Отсюда два неприятных следствия. Само присваивание не даёт эффекта, на который рассчитывает читатель кода. А последующие обращения к имени работают не с вашим значением, а с платформенной коллекцией — включая ограничения по среде исполнения: обращение к коллекции в клиентском методе останется недоступным, сколько бы вы ей ни присваивали.

## Примеры

Неправильно:

```bsl
Процедура Тест()
    Справочники = Новый Структура("Код", 1); // <-- запись в свойство глобального контекста
    Справочники.Вставить("Имя", "Товар");    // работает не с вашей структурой
КонецПроцедуры
```

Правильно — выбрать имя, не занятое платформой:

```bsl
Процедура Тест()
    ДанныеСправочника = Новый Структура("Код", 1);
    ДанныеСправочника.Вставить("Имя", "Товар");
КонецПроцедуры
```

Присваивание законно, если имя объявлено в вашем коде — параметром, `Перем`, реквизитом формы или переменной цикла. Тогда оно принадлежит объявленному владельцу, и диагностика не выдаётся:

```bsl
Процедура Тест(Справочники) // имя объявлено параметром — владелец ваш
    Справочники = Новый Структура("Код", 1);
КонецПроцедуры
```

## Отключение

Если в вашей конфигурации такое присваивание применяется намеренно, диагностику можно отключить стандартным образом в настройках анализатора.
