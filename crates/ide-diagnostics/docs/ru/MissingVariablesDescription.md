# Все объявления переменных должны иметь описание (MissingVariablesDescription)

## Описание диагностики

Переменные модуля должны сопровождаться комментарием, поясняющим их назначение. Без такого описания глобальное состояние модуля становится труднее понимать и сопровождать.

Текущая реализация уже, чем абстрактное правило "все переменные должны быть описаны":

- проверяются только module-level объявления `Перем`;
- локальные переменные внутри процедур и функций не проверяются;
- описание может быть как в той же строке, так и в комментарии над объявлением;
- переменные с аннотациями тоже поддерживаются, включая комментарии вокруг аннотаций;
- комментарий, содержащий только `//` без текста, **не** считается описанием
  (пустая строка комментария выдаёт ту же диагностику, что и полное отсутствие
  описания);
- комментарий-ссылка (`См. ОбщегоНазначения.<имя>` / `See Common.<name>`)
  считается делегированной документацией и диагностику не выдаёт — в
  соответствии с поведением `MissingParameterDescription` и
  `MissingReturnedValueDescription`.

## Примеры

Неправильно:

```bsl
Перем СтатусОбработки;
```

Правильно:

```bsl
Перем СтатусОбработки; // Текущий статус фоновой обработки данных

// Счётчик обработанных документов за сеанс
Перем КоличествоОбработанных;
```
