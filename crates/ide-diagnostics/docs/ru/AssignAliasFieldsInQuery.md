# Назначение псевдонимов выбранным полям в запросе (AssignAliasFieldsInQuery)

## Описание диагностики

Диагностика проверяет поля в подзапросах и требует, чтобы их псевдонимы были записаны явно через ключевое слово `КАК`.

Такой стиль делает текст запроса предсказуемее и снижает зависимость прикладного кода от автоматических имен, которые платформа строит сама. Если поле выбрано без явного псевдонима, то имя колонки результата может поменяться после переименования реквизита или оказаться неочевидным для составного выражения.

Особенно это заметно у составных выражений вроде `Товары.Поставщик.Наименование`, где автоматически сформированное имя поля не всегда совпадает с тем, которое разработчик ожидает увидеть в коде обработки результата.

Диагностика также считает ошибкой неявный псевдоним без ключевого слова `КАК`, например `Товары.Цена ЦенаПродажи`. Поля со звёздочкой (`*`, `Таблица.*`) не проверяются. Во второй и последующих частях конструкции `ОБЪЕДИНИТЬ` поля не анализируются.

## Примеры

```bsl
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|   Товары.Артикул,                              // Неправильно: нет псевдонима
|   Товары.Артикул КАК АртикулТовара,            // Правильно
|   Товары.Цена ЦенаПродажи                      // Неправильно: нет КАК перед псевдонимом
|ИЗ
|   Справочник.Номенклатура КАК Товары           // Игнорируется (источник)
|
|ОБЪЕДИНИТЬ ВСЕ
|
|ВЫБРАТЬ
|   Услуги.Артикул,                              // Игнорируется (вторичный запрос)
|   Услуги.Артикул,                              // Игнорируется
|   Услуги.Тариф                                 // Игнорируется
|ИЗ
|   Справочник.Услуги КАК Услуги";               // Игнорируется

Запрос2 = Новый Запрос;
Запрос2.Текст =
"ВЫБРАТЬ
|   Данные.ИмяТовара КАК ИмяТовара
|ИЗ
|   (ВЫБРАТЬ
|       Товары.Наименование ИмяТовара            // Неправильно: пропущено КАК
|   ИЗ
|       Справочник.Номенклатура КАК Товары) КАК Данные";
```
