# Одинаковые выражения по обе стороны оператора (IdenticalExpressions)

## Описание диагностики

Диагностика выявляет два вида подозрительных конструкций:

1. **Одинаковые выражения по обе стороны оператора** -- когда оператор
сравнения, логический оператор или арифметическая операция (`<`, `>`, `<=`,
`>=`, `=`, `<>`, `И`, `ИЛИ`, `-`, `/`) имеет одинаковые подвыражения слева и
справа, это обычно указывает на ошибку копирования или невнимательность.

2. **Повтор одного и того же выражения в логической цепочке, разбитой
препроцессором** -- когда выражение разделено конструкцией
`#Если/#Иначе/#КонецЕсли` или схожими директивами и в разных ветвях
повторяется один и тот же операнд или условие, условная компиляция теряет
смысл и, скорее всего, содержит ошибку.

## Примеры

### Дублирование выражений по обе стороны оператора

Неправильно:
```bsl
Если Количество > 0 И Количество > 0 Тогда
    ОбработатьДанные();
КонецЕсли;
```

Правильно:
```bsl
Если Количество > 0 И Цена > 0 Тогда
    ОбработатьДанные();
КонецЕсли;
```

Или, если дублирование было лишним:
```bsl
Если Количество > 0 Тогда
    ОбработатьДанные();
КонецЕсли;
```

### Идентичный код в ветвях препроцессора

Неправильно:
```bsl
РежимРаботы =
#Если Сервер Тогда
    РежимРаботыСервера
#Иначе
    РежимРаботыСервера
#КонецЕсли
    И ПравоДоступа("Чтение", Метаданные.Справочники.Контрагенты);
```

Правильно:
```bsl
РежимРаботы =
#Если Сервер Тогда
    РежимРаботыСервера
#Иначе
    РежимРаботыКлиента
#КонецЕсли
    И ПравоДоступа("Чтение", Метаданные.Справочники.Контрагенты);
```

## Источники

Для этой диагностики нет прямого нормативного стандарта 1С. Это локальная
generic-проверка на подозрительные выражения, реализованная в `bsl-analyzer`.
