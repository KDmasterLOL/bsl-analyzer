# Разыменование ссылочных полей запроса через точку (QueryNestedFieldsByDot)

## Описание диагностики

Диагностика выявляет разыменование ссылочных полей через точку внутри текста
запроса.

Публичная логика правила связана с производительностью: такие выражения могут
порождать неявные соединения и делать выполнение запроса менее предсказуемым.
На практике связанные данные часто понятнее и эффективнее получать через явные
`JOIN`.

Текущая реализация покрывает несколько вариантов:

- обычное вложенное обращение к полям в `SELECT`, `WHERE` и `JOIN`;
- разыменование внутри параметров виртуальных таблиц;
- разыменование после `ВЫРАЗИТЬ`.

## Примеры

Неправильно:

```bsl
ВЫБРАТЬ
    Продажи.Контрагент.Наименование КАК КонтрагентНаименование
ИЗ
    Документ.Продажи КАК Продажи
```

Правильно:

```bsl
ВЫБРАТЬ
    Контрагенты.Наименование КАК КонтрагентНаименование
ИЗ
    Документ.Продажи КАК Продажи
    ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Контрагенты
    ПО Продажи.Контрагент = Контрагенты.Ссылка
```

## Параметры

| Параметр       | Тип   | По умолчанию | Описание |
|----------------|-------|--------------|----------|
| `minPathDepth` | `int` | `3`          | Минимальное количество частей пути (через точку) в обычной колоночной ссылке внутри `SELECT` / `WHERE` / `JOIN`, при котором срабатывает диагностика. Значение по умолчанию `3` ловит разыменования глубиной два уровня и более, например `T.Ссылка.Поле`. Меньшие значения расширяют покрытие (`2` ловит любое одиночное разыменование вида `T.Поле`); большие значения сужают его. Значения меньше `2` ограничены жёстким порогом — однокомпонентный идентификатор не содержит разыменования. |

Параметр `minPathDepth` действует только на обычные колоночные ссылки. Разыменования
внутри параметров виртуальных таблиц и цепочки членов после `ВЫРАЗИТЬ` имеют собственный
порог, заложенный в синтаксис конструкции, и эмитятся всегда — вне зависимости от
этого параметра.

Чтобы полностью отключить диагностику, используйте штатный флаг активации, а не
`minPathDepth`.
