## Критические факторы

### 1. XML парсинг доминирует

**Проблема:**
- 84% размера — XML метаданные
- XML парсинг медленнее BSL (~50 MB/s vs 225 MB/s)

**Решение:**
- `quick-xml` — самый быстрый XML парсер в Rust
- Salsa: метаданные загружаются 1 раз, далее кеш с `Durability::HIGH`

**Эффект:**
- БЕЗ кеша: каждая диагностика → парсинг 102 MB → 2+ сек → 40 диагностик = 80 сек
- С Salsa: парсинг 1 раз → 2 сек, далее < 1 ms → **экономия 78 секунд**

### 2. Количество файлов (111K)

**Вызов:**
- VFS должна отслеживать 111K файлов
- Индексация может быть медленной

**Решение:**
- PathInterner (эффективный string interning)
- DashMap (lock-free concurrent hashmap)
- Watch API для отслеживания изменений (не re-scan всей FS)

### 3. Salsa — критична для масштабирования

**Сценарий 1: БЕЗ Salsa**
```
Каждый запрос диагностики → парсинг метаданных
40 Tier 3 диагностик × 2 сек = 80 секунд только на метаданные ❌
Проект был бы лишь ~2x быстрее Java
```

**Сценарий 2: С Salsa**
```
Парсинг метаданных 1 раз → 2 секунды
Последующие запросы → кеш → < 1 ms
40 диагностик × 0.001 сек = 0.04 секунды ✅
Итого: 2.04 сек вместо 80 сек → 200x-360x улучшение!
```

### 4. I/O Performance

**Чтение 4GB с диска:**
```
HDD (100 MB/s):   40 секунд
SSD (500 MB/s):   8 секунд
NVMe (3000 MB/s): 1.3 секунды
```

**Оптимизации:**
- Salsa кеширует file contents
- VFS отслеживает изменения (не перечитывает неизменные)
- Incremental: читаем только измененные файлы

### 5. Параллелизм (Rayon)

**Парсинг:**
```rust
files.par_iter()
    .map(|file_id| db.parse(*file_id))  // Salsa thread-safe!
    .collect::<Vec<_>>();
```

**Эффект:** 8 cores → 8x ускорение для парсинга

## Настройки для больших проектов

### LRU размеры

**Для проектов 121 MB (pt_erp):**
```rust
#[salsa::tracked(lru = 128)]
fn parse(db: &dyn Db, file_id: FileId) -> Parse { ... }

#[salsa::tracked(lru = 256)]
fn analyze(db: &dyn Db, file_id: FileId) -> Analysis { ... }
```

**Для проектов 4GB+:**
```rust
#[salsa::tracked(lru = 512)]  // Больше кеша
fn parse(db: &dyn Db, file_id: FileId) -> Parse { ... }

#[salsa::tracked(lru = 512)]
fn analyze(db: &dyn Db, file_id: FileId) -> Analysis { ... }
```

**Trade-off:**
- Больший LRU = больше памяти (~256 MB для LRU=512), меньше cache misses
- Меньший LRU = меньше памяти, больше перепарсивания

### Durability для метаданных

```rust
#[salsa::tracked(lru = 16, durability = Durability::HIGH)]
fn load_configuration(db: &dyn Db, path: ConfigPathInput) -> Arc<Configuration> {
    // Метаданные меняются редко → HIGH durability
    // Малый LRU (обычно 1 конфигурация активна)
}
```
