# Рабочий контур для `workspace`

## Общая схема

Контур `workspace` работает с двумя источниками:

- общим baseline из PostgreSQL;
- локальным overlay из текущей рабочей копии.

Итоговый поиск строится как merge этих двух частей.

## Выбор baseline

На старте рабочий контур:

1. читает политику веток из конфигурации проекта;
2. определяет текущую ветку рабочей копии;
3. выбирает baseline snapshot;
4. вычисляет состояние поддержки ветки: `ready`, `stale` или `expired`.

Если ветка считается `expired`, workspace search блокируется до обновления
ветки от `develop`.

## Полнотекстовый поиск (`find_code`)

Текущее поведение:

1. проверяется, разрешён ли workspace search для выбранной ветки;
2. контур пытается выполнить прямой полнотекстовый поиск по внешнему baseline;
3. затем результаты объединяются с локальным overlay;
4. если прямой serving недоступен, используется резервный переход к resolved view или локальному SQLite.

## Семантический поиск (`search_code`)

Текущее поведение:

1. проверяется состояние ветки;
2. проверяется состояние семантического контура (`ready`, `warming up`, `failed`);
3. при готовности выполняется прямой семантический поиск по внешнему baseline;
4. результаты объединяются с локальным семантическим overlay;
5. при недоступности serving path используется резервный переход к локальному семантическому индексу.

Если semantic warmup ещё идёт, пользователю явно предлагается временно
использовать `find_code`.

## Что хранится локально

Даже при общем baseline у `workspace` остаётся локальное состояние:

- полнотекстовый индекс overlay;
- семантический индекс overlay;
- статистика и состояние overlay;
- локальный резервный кэш и служебное состояние.

Это сознательное решение: локальные незакоммиченные изменения должны быть
видны сразу, без публикации в общий backend.

## Что показывает `search(action=status)`

Статус для `workspace` умеет показывать:

- настроенный baseline и выбранный snapshot;
- состояние поддержки ветки и причина;
- источник полнотекстового и семантического поиска;
- параметры прогрева семантического индекса;
- состояние resolved workspace view;
- статистику overlay: количество файлов, hidden paths, chunks, cached embeddings.
