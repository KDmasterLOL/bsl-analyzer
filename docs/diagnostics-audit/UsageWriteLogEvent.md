# UsageWriteLogEvent

Статус: `done`, `needs-code-work`

## Суть правила

Проверяет корректность вызова `ЗаписьЖурналаРегистрации` / `WriteLogEvent`, особенно внутри `Исключение`.

## Проверенные источники

- `<v8std mirror>/docs/std/498.md`
- `<v8std mirror>/docs/std/499.md`

## Как реализовано

HIR передает флаги: блок `Исключение`, число аргументов, пустой уровень, пустой комментарий, уровень `Ошибка`, наличие `ПодробноеПредставлениеОшибки`, наличие `ВызватьИсключение`. Внутри `Исключение` lowering трассирует переменную-комментарий через присваивания, конкатенации и обёртки (`СтроковыеФункции…`), распознаёт квалифицированный `ОбработкаОшибок.ПодробноеПредставлениеОшибки`. Handler возвращает первую найденную проблему.

## Что покрыто

Покрыты неправильное число параметров, пустой 2-й/5-й параметр, запись внутри exception без уровня `Ошибка` и без подробного описания/raise.

## Пробелы и ограничения

Возвращается только первая проблема на вызов. Нет fix для добавления недостающих аргументов.

## Может ли инфраструктура улучшить качество

Да. Нужен multi-diagnostic или structured sub-issues, плюс шаблонный fix для exception logging.

## Возможное объединение

Близко к `MissingCodeTryCatchEx`, `TryNumber`, transaction/exception diagnostics. Общий exception-handling analyzer нужен.

## Вывод

Правило покрывает важный стандарт логирования, но может скрывать несколько нарушений в одном вызове.
