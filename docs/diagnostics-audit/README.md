# Аудит диагностик

Эта папка предназначена для последовательного разбора диагностик
`ide-diagnostics`.

Порядок прохода фиксированный: алфавитный порядок `DiagnosticCode` из
`crates/ide-diagnostics/src/code.rs`. Для каждой диагностики заводится отдельный
файл в этой папке.

## Что проверяем

- какие rule-доки и provenance-доки есть у диагностики;
- на какие внешние источники ссылаются rule-доки;
- какие кейсы реально покрывает текущая реализация и тесты;
- какие кейсы покрыты частично или не покрыты;
- позволяет ли текущая инфраструктура улучшить качество диагностики;
- есть ли близкие по смыслу диагностики и стоит ли рассматривать объединение
  handler'ов, общего анализа или документации;
- какие ограничения есть сейчас и какие варианты их снятия выглядят реалистично.

## Источники для каждой карточки

- `crates/ide-diagnostics/src/code.rs` — код диагностики и общий порядок;
- `crates/ide-diagnostics/src/handlers/*.rs` — реализация и тесты;
- `crates/ide-diagnostics/docs/ru/*.md` и `crates/ide-diagnostics/docs/en/*.md`
  — пользовательская документация правила;
- `docs/legal/diagnostics/*.md` — provenance и clean-room статус;
- `/home/itrous/src/tools_migration/lsp/v8std/docs/diagnostics/bslls/*.md` —
  карточки BSLLS в локальном репозитории `v8std`;
- `/home/itrous/src/tools_migration/lsp/v8std/docs/std/*.md` — тексты
  стандартов, если карточка BSLLS на них ссылается;
- смежные слои `hir`, `cfg`, `dataflow`, `bsl-metadata`, если диагностика на них
  опирается.

## Статусы

- `done` — диагностика разобрана и есть вывод по качеству;
- `needs-code-work` — найдены ограничения, которые стоит переводить в задачи;
- `blocked` — не хватает источника, инфраструктуры или ясного правила;
- `skipped` — запись не является активной диагностикой из `DiagnosticCode`.
