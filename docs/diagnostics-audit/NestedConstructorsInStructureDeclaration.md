# NestedConstructorsInStructureDeclaration

Статус: `done`, `needs-code-work`
Дата разбора: 2026-05-07

## Суть правила

Запрещает использовать конструкторы с параметрами внутри объявления `Структура` / `ФиксированнаяСтруктура`.

## Проверенные источники

- `crates/ide-diagnostics/src/handlers/nested_constructors_in_structure_declaration.rs`
- `crates/ide-diagnostics/src/runner.rs`
- `<v8std mirror>/docs/diagnostics/bslls/NestedConstructorsInStructureDeclaration.md`

## Как реализовано

HIR-обход по `Expr::New`. Если создается `Структура`, `Structure`, `ФиксированнаяСтруктура` или `FixedStructure` с несколькими аргументами, обработчик ищет среди аргументов вложенный `Expr::New` с непустым списком параметров.

## Что покрыто

Покрыты русские и английские имена типов, вложенные структуры с параметрами, отсутствие срабатывания для пустой вложенной структуры и для одиночного параметра.

## Пробелы и ограничения

Проверяется только непосредственный аргумент-конструктор. Вложенность через переменную или вызов фабрики не видна. Нет fix для предварительного вынесения вложенного конструктора в отдельную переменную.

## Может ли инфраструктура улучшить качество

Частично. Dataflow может найти больше случаев, но автоматическое исправление потребует safe statement insertion и именования временной переменной.

## Возможное объединение

Близко к `NestedFunctionInParameters` и общему семейству readability diagnostics. Возможен общий nested-expression detector с настройками по типу контекста.

## Вывод

Правило хорошо покрывает прямой паттерн из стандарта, но не видит семантически эквивалентные случаи через переменные/фабрики.
