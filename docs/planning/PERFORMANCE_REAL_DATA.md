**Оценка:**

| Компонент | Размер | Пояснение |
|-----------|--------|-----------|
| VFS (FileId mapping) | ~10 MB | PathInterner (111K файлов) |

| Метаданные (Configuration) | ~120 MB | Arc-shared, loaded once |
| Symbol tables | ~50 MB | Name → Definition |

**Экстраполяция на 4 GB:**
```
490 MB * (4000 / 121) = 16.2 GB
```

**Но LRU ограничит:**
- Parse cache: 128-512 файлов = 64-256 MB (фиксировано)
- HIR cache: 256-512 = 128-256 MB (фиксировано)
- Метаданные: ~4 GB * 0.84 (XML доля) = 3.3 GB (loaded once)

**Итого для 4 GB:** ~4-5 GB (вместо 99 GB на Java)

## Критические факторы

### 1. XML парсинг доминирует

**Проблема:**
- 84% размера — XML
- XML парсинг медленнее BSL (~50 MB/s vs 225 MB/s)

**Решение:**
- Использовать `quick-xml` (самый быстрый XML парсер в Rust)
- Salsa: загружать метаданные 1 раз, далее кеш

### 2. Количество файлов огромно (111K)

**Проблема:**
- VFS должна отслеживать 111K файлов
- Индексация может быть медленной

**Решение:**
- Эффективные структуры данных (PathInterner, DashMap)
- Watch API для отслеживания изменений (не re-scan всей FS)

### 3. Salsa — критична для метаданных

**Без Salsa:**
- Каждый запрос диагностики → парсинг 102 MB XML → 2+ секунды
- 40 Tier 3 диагностик → 40 * 2 = 80 секунд только на метаданные!

**С Salsa:**
- Парсинг 1 раз → 2 секунды
- Последующие запросы → кеш → < 1 мс
- **Экономия: 80 секунд → 2 секунды**
